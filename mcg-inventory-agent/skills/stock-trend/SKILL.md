# Task: Stock Trend Analysis

## Step 0 — เรียก `max_stock_date_synapse` ครั้งแรกของ conversation (anchor)

⚠️ "ล่าสุด" หมายถึง **วันสต็อก snapshot ล่าสุด** ไม่ใช่วันนี้ — ห้ามใช้วันที่ปัจจุบันของระบบ (ข้อมูล lag ได้)
- end_date = `max_date` จาก anchor | YoY → ใช้ `snap_prev` (วันเดียวกันปีก่อน) / `fy_curr_start` / `fy_prev_start`

## Step 1 — กำหนดช่วงเวลา (บังคับ)

⚠️ ตาราง historical ใหญ่มาก — ต้องมี start/end date เสมอ (รูปแบบ `YYYY-MM-DD`)
- ถ้า user ไม่ระบุช่วง → **ถามกลับ** (เช่น "ต้องการดูย้อนหลังกี่วัน/เดือนครับ?")
- ถ้า user ถาม **"จำนวน/กี่" ลอย ๆ ไม่ระบุหน่วย** → **ถามกลับ**ก่อน (เช่น "ต้องการนับเป็น SKU / รุ่น-สี / ชิ้น ครับ?") — ห้ามเดาแล้วตอบตัวเลขเดียว
- default ที่แนะนำ: `max_date` ย้อนหลัง 30 วัน หรือรายเดือนย้อน 3 เดือน (อิง anchor)

## Step 2 — ดึง trend

เรียก `stock_daily_trend_synapse(start_date=..., end_date=..., group_by=<optional>)`

ผลลัพธ์ให้: stock ตามวัน/ช่วง แยก dimension ที่เลือก (เช่น aging, brand)

> ⚠️ **นับ "จำนวนรุ่น" ต้องนับที่รุ่น-สี เท่านั้น** — ไม่ใช่รุ่น และไม่ใช่ SKU · ตรวจ 2026-09-26: SKU 128,121 · รุ่น 23,815 · รุ่น-สี 31,418 (คลาด ~32%)
> ✅ trend ที่ถาม "จำนวนรุ่น" → group แล้วนับ distinct รุ่น-สี · 🚫 ห้ามใช้ระดับ `Article_Model` ตอบ "จำนวนรุ่น"

> ⚠️ **ถ้า user ขอเทียบปีก่อน (YoY):** tool นี้ให้ trend ช่วงเดียว — ต้องทำ Apple-to-Apple ผ่าน `inventory_query_synapse` ด้วย conditional SUM (snapshot วันเดียวกันปีก่อน) ตาม §5.5 ของ foundation

## Step 3 — Response

**Headline** — ทิศทางสต็อก (เพิ่ม/ลด) ช่วงที่เลือก + %change

**ตาราง: Stock Trend**

> ⚠️ ทุกคอลัมน์ที่เป็นจำนวนต้องมีหน่วยในหัวคอลัมน์เสมอ · ถ้าคำถามเป็นแนวโน้ม "จำนวนรุ่น" ให้เพิ่มคอลัมน์ **จำนวนรุ่น-สี** (ห้ามใช้ "จำนวนรุ่น" ลอย ๆ)

**Key Insights** — สต็อกสะสมขึ้น/ลง, aging zone ที่โตเร็ว (สัญญาณสินค้าค้าง), ช่วงที่เติมของเข้ามาก

> ⚠️ **"ช่วงที่เติมของเข้ามาก / รับของเข้า / Sales In / GR" ให้ตอบจำนวนชิ้น (qty) เป็นหลัก** — มูลค่า (บาท / PO value) ใส่เมื่อผู้ใช้ถามเรื่องมูลค่าเอง และต้องแยก **สั่ง (PO) · รับเข้าแล้ว (GR) · ค้างส่ง** พร้อมระบุ as-of

# Output Rules
- ต้องมี date range เสมอ
- ระบุชัดว่าเป็น snapshot ณ วันไหน หรือค่าเฉลี่ยช่วง
- เปรียบเทียบต้นช่วง vs ปลายช่วงเพื่อบอกทิศทาง
- ห้ามตีความ NULL เป็น 0

_กฎบังคับจาก foundation (§"กฎการนับจำนวน" / §"กฎการตอบเรื่องรับของเข้า") — สรุปเฉพาะที่ skill นี้ใช้บ่อย:_
- **ทุกจำนวนต้องมีหน่วยกำกับ** — "กี่ SKU" / "กี่รุ่น-สี" / "กี่ชิ้น" · ห้ามปล่อยตัวเลขลอย และห้ามใช้คำว่า "จำนวน" เดี่ยว ๆ ในหัวตาราง
- **"จำนวนรุ่น" = รุ่น-สี** — ไม่ใช่รุ่น และไม่ใช่ SKU
- **"จำนวน/กี่" ที่ไม่ระบุหน่วย → ถามกลับก่อน** ห้ามเดาแล้วตอบตัวเลขเดียว
- **รับของเข้า (Sales In / GR) → ตอบจำนวนชิ้นเป็นหลัก** · มูลค่า (บาท / PO value) ใส่เมื่อผู้ใช้ถามเรื่องมูลค่าเอง
