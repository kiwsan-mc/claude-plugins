# MCG Ads Agent

MC Group Ads Agent plugin for Claude Code / Cowork / Claude Desktop.

วิเคราะห์ผลโฆษณาของ MC Group ทั้ง **TikTok Ads** และ **Shopee Ads** — การใช้เงินเทียบผลตอบแทน (ROAS/ROI), ยอดขายจากแอด, โครงสร้างแคมเปญ, สุขภาพการวัดผล (pixel), กลุ่มเป้าหมาย — แล้วเชื่อมกับออเดอร์และสต็อกที่ MC Group มีอยู่จริง เพื่อตอบคำถามว่า **"โฆษณาคุ้มไหม และควรทำอะไรต่อกับงบก้อนถัดไป"** ไม่ใช่แค่รายงานตัวเลข

## Skills

| Skill | ทำอะไร |
|---|---|
| `ads-review` | ทบทวนผลโฆษณาครบวงทั้งสองช่องทาง: สถานะบัญชี · งบรายวัน · แคมเปญที่กินงบ · โครงสร้าง/สถานะ · pixel และ audience · เทียบกับออเดอร์ที่ยังไม่จัดส่ง |

## สองช่องทางให้ข้อมูลต่างกัน

| | TikTok Ads | Shopee Ads |
|---|---|---|
| ยอดขายจากแอด (GMV) | ❌ ไม่มี | ✅ มี |
| ROAS | ⚠️ ระดับบัญชีเท่านั้น | ✅ มีทั้ง direct และ broad |
| จำนวนออเดอร์จากแอด | ❌ | ✅ |
| โครงสร้างแคมเปญ/โฆษณา | ✅ ละเอียด | ⚠️ แค่รายการแคมเปญ |
| การวัดผล (pixel, audience) | ✅ | ❌ |

▸ **ถาม "ยอดขายจากโฆษณา" หรือ "ROAS" ให้เริ่มที่ Shopee** เพราะเป็นช่องทางเดียวที่ตอบด้วยตัวเลขจริง

## Setup

Plugin นี้ **ไม่ประกาศ MCP server ของตัวเอง** — ข้อมูลทั้งหมดมาจาก connector **MC E-Commerce & Ads** ที่มีอยู่แล้ว

ถ้ายังไม่เห็น connector นี้ ให้เพิ่มก่อนใช้งาน ไม่งั้น skill จะเรียก tool ไม่ได้และจะบอกผู้ใช้ตรง ๆ ว่าให้เพิ่ม connector (ไม่ตอบจากความจำแทน)

## ข้อจำกัดที่ skill จะบอกผู้ใช้เสมอเมื่อเกี่ยวข้อง

- **กำไร/กำไรขั้นต้น** — ไม่มี COGS ไปได้ไกลสุดแค่ ROAS
- **โฆษณา Lazada** — ยังไม่มีข้อมูล มีแต่ TikTok Ads และ Shopee Ads
- **ที่เชื่อม ad ↔ SKU** — ยังไม่มีทั้งสองช่องทาง จึงไม่รู้ว่าแอดตัวไหนผูกสินค้าตัวไหน
- **ROAS รายแคมเปญบน TikTok** — มักไม่มีค่า ต้องอ่านค่าจริงและรายงาน "ไม่มีข้อมูล" ไม่ใช่ 0
- **ผลรายแคมเปญของ Shopee** — แคมเปญที่ดูมายังไม่พบที่มียอด จึงยังไม่มีตัวอย่างจริง
- **แคมเปญแบบ GMS ของ Shopee** — ถูกจำกัดการเรียกไว้ ยังอ่านไม่ได้

## กฎที่ skill ยึด

- ห้ามเดาตัวเลข — ทุกตัวต้องมาจากผลการเรียก tool ในบทสนทนานั้น
- metric ที่หายไปจากผลลัพธ์ **ไม่ใช่ 0** — หมายถึงผู้ให้ข้อมูลไม่มีค่าให้ ณ จุดนั้น
- ทุกจำนวนมีหน่วย · ยอดรวมต้องเท่ากับผลบวกของแถวที่แสดง
- ตัวเลขกำไร/จุดคุ้มทุนต้องตีตราว่าเป็นการประมาณ และระบุว่าต้องยืนยันกับใคร
- ห้ามพิมพ์ชื่อ tool/field/ตารางในคำตอบที่ผู้ใช้เห็น

## Version

**v1.7.0** — ยอดขายมีสองนาฬิกา และห้ามจับคู่ผิด
- แยกให้ชัด: **ยอดขายคลัง (day-1)** สำหรับรายงานบริษัท/กำไร/เทียบเป้า · **ยอดขายอีคอมเมิร์ซ (realtime)** สำหรับดูว่าแอดได้ผลไหม
- 🚫 ห้ามเอางบโฆษณาไปหารด้วยยอดขายคลัง — คนละนาฬิกา และอันตรายเพราะตัวเลขดูสมเหตุสมผล
- ✅ ยอดที่ใช้คู่กับงบโฆษณาให้ใช้ยอดที่แพลตฟอร์ม attribut ให้เอง (Shopee `broad_gmv`/`direct_gmv` · TikTok ประมาณจาก ROAS × งบ และต้องติดป้าย)
- คำถามยอดขายบริษัท → ส่งต่อ `mcg-sales-agent` ไม่ใช่ประกอบจากออเดอร์ที่นี่
- ทุกยอดขายที่รายงานต้องบอกแหล่งและ as-of

**v1.6.0** — สอนวิธีหารอบแคมเปญจากข้อมูลเอง
- เพิ่มขั้นตอน 6 ข้อที่ agent ทำได้เองด้วยเครื่องมือที่มี: แบ่งหน้าต่างละเดือน → จัดกลุ่มตามวันของเดือน → หาค่ามัธยฐานเป็นเส้นฐาน → หาวันที่ ≥1.3 เท่า → **ตัดวัน Double Day ออกแล้ววัดซ้ำเพื่อแยกรอบเงินเดือนออกจากวันแคมเปญ** → ยืนยันด้วยชื่อแคมเปญ
- เกณฑ์ความมั่นใจ: เห็นรอบเดิม ≥3 ครั้งจึงเรียกว่า "รอบ" · 1-2 ครั้งให้บอกว่ายังสรุปไม่ได้
- 🚫 ห้ามตอบว่า "วันจ่ายเงินเดือนคือวันที่ X" — ให้พูดว่า "งบพุ่งซ้ำที่วันที่ X ใน N รอบที่ดูมา" ซึ่งเป็นสิ่งที่วัดได้จริง
- ใช้มัธยฐานไม่ใช่ค่าเฉลี่ย เพราะวันแคมเปญใหญ่ลากค่าเฉลี่ยจนมองไม่ออก

**v1.5.0** — วัดรอบ payday จากข้อมูลจริง
- วัดจากงบโฆษณา Shopee รายวัน 6 เดือน (180 วัน) ตัดวัน Double Day ออก: **วันที่ 25 สูง ~2.1 เท่า** · **วันที่ 15 สูง ~1.8 เท่า** · **วันที่ 1–10 ไต่ขึ้นถึง ~2.0 เท่า** · **วันที่ 18–24 ต่ำสุด ~0.6 เท่า**
- ข้อสรุปที่ตามมา: งบไม่ได้วิ่งเท่ากันทุกวัน การดูวันเดียวหรือค่าเฉลี่ยรวมจะสรุปผิดทิศ
- ตัวเลขอยู่ในบล็อกที่มีวันที่กำกับและคำเตือนห้ามนำไปตอบโดยตรง — ตามกฎของรีโปนี้ที่ห้ามปักค่าที่เปลี่ยนได้
- พบเพดานใหม่ของ Shopee: ช่วงวันต่อการเรียกของรายวันสั้นกว่าที่คิด (~1 เดือน ไม่ใช่ 6 เดือน) ต้องแบ่งหน้าต่าง

**v1.4.0** — แยกรอบแคมเปญเป็นสองแบบ เพราะกฎการเทียบไม่เหมือนกัน
- **Double Day (รายปี)** — 1.1 ถึง 12.12 · เทียบข้ามปีทำไม่ได้เพราะข้อมูลไม่ย้อนถึง
- **payday (รายเดือน)** — กลางเดือน และปลายเดือน/ต้นเดือนถัดไป · **เทียบเดือนต่อเดือนได้** เพราะย้อนได้ 6 เดือน เห็นหลายรอบ
- ห้ามสมมติว่าวันไหน — ให้อ่านจากชื่อแคมเปญ (ตัวอ่านเดียวที่คืนชื่อ) และจากรูปแบบงบที่พุ่งซ้ำทุกเดือน

**v1.3.0** — รู้จักช่วงแคมเปญใหญ่ (Double Day)
- ระบุวันแคมเปญ 1.1 ถึง 12.12 พร้อมขนาดโดยประมาณ (12.12 ใหญ่สุด · 11.11 รองลงมา) และตีความว่าผู้ใช้หมายถึง "รอบของวันนั้น" ไม่ใช่วันเดียว
- กฎการเทียบ: ห้ามเทียบวันแคมเปญใหญ่กับวันปกติ · เทียบแบบเดียวกันกับเดียวกัน · และ **เทียบข้ามปีทำไม่ได้** เพราะข้อมูลไม่ย้อนถึง ต้องบอกตรง ๆ ไม่ใช่ประมาณ
- ถ้าช่วงที่ดูตรงกับวันแคมเปญใหญ่ ให้ระบุในคำตอบว่างบที่พุ่งอาจเป็นเรื่องปกติของรอบ ไม่ใช่การยิงผิด

**v1.2.0** — Shopee Ads ครบ 11 tools
- เพิ่มข้อมูล **รายชั่วโมง** (ทั้งระดับร้านและระดับแคมเปญ) — เห็นไลฟ์อีเวนต์เผางบระหว่างเกิด ไม่ต้องรอข้ามคืน
- เพิ่ม **การตั้งค่าแคมเปญ** ซึ่งเป็นตัวเดียวที่คืน "ชื่อแคมเปญ" ทำให้ id อ่านออก
- เพิ่ม **การวางแผน**: สินค้าที่แนะนำ · คำค้นพร้อมปริมาณการค้นหาและราคาเสนอ · ช่วงเป้าผลตอบแทนต่อสินค้า
- กับดักที่เพิ่มเข้ามา: รายชั่วโมงรับวันเดียวไม่ใช่ช่วง · การตั้งค่าแคมเปญต้องส่งสองอย่าง · เป้าผลตอบแทนรับ item id ไม่ใช่ campaign id · และตัวเลขจากข้อ "วางแผน" ห้ามนำไปรวมกับผลงานที่ผ่านมา

**v1.1.0** — เพิ่ม Shopee Ads และเปลี่ยนชื่อ skill เป็น `ads-review` ให้ครอบสองช่องทาง
- Shopee Ads ให้สิ่งที่ TikTok ไม่มี: ยอดขายจากแอด (GMV), ROAS ทั้ง direct และ broad, จำนวนออเดอร์ และหน่วยที่ขายได้ — ข้อจำกัดเดิมที่ว่า "ยอดขายจากโฆษณาประมาณได้จาก ROAS × spend เท่านั้น" จึงมีคำตอบจริงแล้วในฝั่ง Shopee
- skill จึงเริ่มจาก Shopee เมื่อถูกถามเรื่องยอดขายจากโฆษณา และเริ่มจากระดับบัญชีเมื่อถาม TikTok พร้อมบอกตรง ๆ ว่าต่ำกว่านั้นไม่มีข้อมูล
- กับดักที่ใส่มา: วันที่ต้องเป็น `YYYY-MM-DD` (tool แปลงให้) · ย้อนได้ไม่เกิน 6 เดือน · ผลรายแคมเปญของ Shopee ต้องมี campaign id และแถวศูนย์แปลว่าไม่มีการใช้เงิน ไม่ได้แปลว่าแย่
