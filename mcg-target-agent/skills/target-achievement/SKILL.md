# Task: Target vs Actual Analysis

## Step 1 — เลือก dimension + ช่วงเวลา

`sales_target_vs_actual_synapse` รองรับ group_by: `channel`, `branch`, `cluster`, `month`, `day`
- ถ้าไม่ระบุ → default `channel`
- filter ด้วย year/month ได้ (ถ้าไม่ระบุ = 'all')
- ⚠️ **ไม่มี `category`** — ตารางเป้าใหม่เก็บเป้าระดับสาขา × วัน เท่านั้น ถ้า user ขอเป้าแยกหมวดหมู่สินค้า ให้แจ้งตรง ๆ ว่าเป้าไม่มีมิติ category แล้วเสนอ แยกช่องทาง/สาขา/cluster/เดือน แทน — **ห้ามดึงเป้าจากที่อื่นมาแทน**

## Step 2 — ดึงข้อมูล

⚠️ **ต้องใส่ `start_date` / `end_date` ทุกครั้ง — ห้ามเรียกด้วย `group_by` อย่างเดียว** (ไม่ใส่ = สแกนทั้งตาราง ~900M แถว = 60–100 วิ)

🚫 **ห้ามส่ง `year` / `month` โดยไม่มี `start_date` / `end_date` เด็ดขาด** — tool จะเอาเป้า**เต็มเดือน**เป็นตัวหาร แต่ยอดจริงมีแค่ถึงวันที่ข้อมูลล่าสุด → **achievement ต่ำเกินจริงมาก**
> 📏 วัดจริง 2026-09-24: `year=2026, month=9` อย่างเดียว → เป้า ฿418,335,300 (**30 วัน**) ÷ ยอดจริง ฿269,196,499 = **64.35%** ❌
> ใส่ `start_date=2026-09-01, end_date=2026-09-23` → เป้า ฿314,462,269 (**23 วัน**) ÷ ยอดเดียวกัน = **85.61%** ✅
> ⇒ **ต่างกัน 21 คะแนน** จากเรื่องช่วงเวลาเพียงเรื่องเดียว (เป้าหลัง 23 ก.ย. = ฿103.87M ที่ยังไม่ถึงวัน)

เรียก `sales_target_vs_actual_synapse(group_by=<dimension>, start_date=..., end_date=..., year=<optional>, month=<optional>)`

**ขั้นบังคับ — หา "วันสุดท้ายที่มีข้อมูลจริง" ก่อนตั้ง `end_date`:**
1. เรียก `sales_target_vs_actual_synapse(group_by='day', start_date=..., end_date=<สิ้นเดือน>)`
2. ดู **วันสุดท้ายที่ `actual_sales` > 0** → นั่นคือขอบข้อมูลจริง (วันถัดไปจะได้ 0 ทั้งที่เป้ามี)
3. ตั้ง `end_date` = วันนั้น แล้วยิงใหม่ด้วย dimension ที่ต้องการ
> ทำไมต้องทำแบบนี้: `fact_sales_and_stock_daily` (แหล่งยอดจริงของ tool นี้) **ไม่อยู่ใน allowlist** ของ agent ตัวนี้ → เห็นขอบข้อมูลได้จาก `group_by='day'` ทางเดียว
> 📏 2026-09-24: วันสุดท้ายที่มียอดจริง = **2026-09-23** (24–30 ก.ย. ได้ 0 แต่เป้ามี ฿103.87M)

**ช่วงเวลามาตรฐาน**
- `month_start` = **วันที่ 1 ของเดือนเดียวกับ `max_date`** — anchor คืนแค่ `max_date` / `same_day_prev` / `fy_curr_start` / `fy_prev_start` **ไม่มี `month_start`** ต้องคำนวณเอง และ 🚫 **ห้ามใช้วันที่ปัจจุบันของระบบ**
- ไม่ระบุช่วง → `month_start` → **วันสุดท้ายที่มีข้อมูลจริง** (ไม่ใช่ `max_date` ดิบ ถ้าสองอันต่างกัน)
- ระบุเดือนที่**จบแล้ว** → `YYYY-MM-01` → วันสุดท้ายของเดือนนั้น
- ระบุเดือน**ปัจจุบัน** → `YYYY-MM-01` → วันสุดท้ายที่มีข้อมูลจริง
- "ทั้งปี/FY นี้" → `fy_curr_start` → วันสุดท้ายที่มีข้อมูลจริง
- ⚠️ **กรองทั้งสองฝั่ง (เป้าและยอดจริง) ด้วยช่วงเดียวกันเสมอ** — ตัวหาร achievement ต้องเป็นช่วงเดียวกับตัวตั้ง
- วัดจริง: ไม่ใส่ช่วง = 79.8 วิ → 1 เดือน = 6.1 วิ
- **บอก user ด้วยว่าใช้ช่วงวันที่ไหน** (เช่น "1–23 ก.ย. 2026") — อย่าปล่อยให้เข้าใจว่าเป็นยอดเต็มเดือน

ผลลัพธ์ให้: dimension_value, target_value, target_weight, actual_qty, actual_sales, achievement_pct

## Step 3 — Response

**Headline** — achievement **MTD** (ตามช่วงข้อมูลจริง) + เป้าเต็มเดือน/คงเหลือเป็น context

⚠️ **กลางเดือนต้องแยกสองตัวเลขให้ชัด** — "ทำเป้าได้กี่ %" = อยากรู้ **MTD**:

| ตัวเลข | ความหมาย |
|---|---|
| **achievement (MTD)** | ยอดจริง ÷ **เป้าถึงวันที่มีข้อมูล** ← ตัวเลขที่ตอบคำถาม ✅ |
| เป้าเต็มเดือน · คงเหลือ | ให้ context — เป้าทั้งเดือน และอีกกี่บาทถึงจะครบ |

**ตาราง: Target vs Actual by [dimension]**
| Dimension | Target (ถึงวันที่มีข้อมูล) | Actual | Achievement% | สถานะ |

(สถานะ: ≥100% 🟢 | 90-99% 🟡 | <90% 🔴)

🚫 **ห้ามนำเป้าเต็มเดือนมาเป็นตัวหาร** ขณะยอดจริงยังไม่ครบเดือน — และห้ามวางสองตัวเลขต่างช่วงไว้บรรทัดเดียวกันโดยไม่กำกับวันที่

### ⚠️ `group_by='branch'` (เช่น "สาขาไหนไม่ถึงเป้า") — ต้องแยก **รหัสสาขา + ชื่อสาขา**

tool คืนสาขาเป็นสตริงเดียว `Branch_Code_And_Text` รูปแบบ **`<รหัส>-<ชื่อ>`** → **ให้แยกเป็น 2 คอลัมน์ในการตอบเสมอ** อย่าปล่อยเป็นก้อนเดียว

| รหัสสาขา | ชื่อสาขา | Target (ถึงวันที่มีข้อมูล) | Actual | Achievement% | สถานะ |
|---|---|---|---|---|---|

- แยกที่ **`-` ตัวแรก**: `S080-Shop Mc Jeansโลตัส สุขุมวิท50` → รหัส `S080` · ชื่อ `Shop Mc Jeansโลตัส สุขุมวิท50`
- ✅ ปลอดภัย: **ไม่มีรหัสสาขาใดมี `-` ในตัวเอง** (ตรวจ 9,405 สาขา = 0) และ `Branch_Code_And_Text` **มีครบทุกสาขา** (ว่าง 0 แถว)
- 🚫 **ห้ามใช้ `Store_Name`** เป็นชื่อสาขา — ว่าง **8,807 จาก 9,405 (93.6%)** ⇒ จะได้ชื่อว่างเกือบทั้งหมด
- ✅ ใช้ชื่อภาษาไทยตาม `Branch_Text` (เช่น "โลตัส กระบี่") ไม่ต้องแปลเป็นอังกฤษ · รหัสสาขาคือส่วนก่อน `-` (ตรงกับ `Branch_Code_Key`)

**Key Insights** — กลุ่มที่ทำเกินเป้า (ดึงจุดแข็ง), กลุ่มที่ห่างเป้ามาก (ต้องเร่ง), gap เชิงปริมาณ

# Output Rules
- achievement% = actual_sales / target * 100 — **และ `target` ต้องเป็นเป้าของช่วงเดียวกับ `actual_sales` เท่านั้น**
- 🚫 ห้ามรายงาน "เป้าเต็มเดือน ÷ ยอดจริงบางส่วน" (ดูตัวอย่าง 64.35% vs 85.61% ใน Step 2)
- ✅ ระบุช่วงวันที่ของตัวเลขทุกครั้ง ("1–23 ก.ย. 2026") และแยก **MTD** ออกจาก **เต็มเดือน**
- ✅ **คำถามระดับสาขา → แสดง "รหัสสาขา" + "ชื่อสาขา" เป็น 2 คอลัมน์เสมอ** (แยกจาก `<รหัส>-<ชื่อ>`) · 🚫 ห้ามใช้ `Store_Name` (ว่าง 93.6%) · ห้ามส่งค่าที่รวมกันเป็นก้อนเดียว
- ใช้ threshold สี 🟢🟡🔴 ตาม achievement
- เรียงจาก achievement ต่ำ→สูง เมื่อเน้นจุดที่ต้องแก้
- ห้ามตีความ NULL/0 actual เป็น "ไม่มีเป้า" — อาจเป็นยังไม่เริ่มขาย **หรือยังไม่ถึงวันนั้น** (วันอนาคตจะได้ 0 เสมอ)
